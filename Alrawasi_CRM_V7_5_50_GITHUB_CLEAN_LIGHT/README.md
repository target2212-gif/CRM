# نظام الرواسي CRM — الإصدار V7.5.50

هذا **مستودع كود فقط** لتشغيل المشروع على Render وربطه بقاعدة Neon الاختبارية/الحية بعد التحقق منها.
لا يحتوي على قاعدة العملاء أو سجلات التواصل الحية؛ ممنوع رفع النسخ الاحتياطية أو ملفات JSON المصدرة من النظام إلى GitHub.

## أين توجد ملفات التشغيل؟

- `render.yaml`: إعداد Render Blueprint من **جذر المستودع**، يحدد `rootDir: Alrawasi_CRM_OneClick_Deploy`.
- `Alrawasi_CRM_OneClick_Deploy/Dockerfile`: بناء التطبيق وتشغيله.
- `Alrawasi_CRM_OneClick_Deploy/app.py`: منطق CRM وواجهات Flask.
- `Alrawasi_CRM_OneClick_Deploy/templates/`: صفحات النظام بما فيها إصلاح ألوان البطاقات.
- `Alrawasi_CRM_OneClick_Deploy/requirements.txt`: متطلبات Python.
- `Alrawasi_CRM_OneClick_Deploy/free_seed_bootstrap.py`: التحقق من صحة القاعدة المستعادة من Neon قبل تشغيل Flask.
- `Alrawasi_CRM_OneClick_Deploy/muqawil_v4_2_catalog.json` و`muqawil_classification_index.json`: ملفا بيانات مرجعية تستخدمهما وظائف محددة من النظام، لذا أُبقيا في الكود.

## ما الجديد؟

- أزرق فاتح لتواصل **خدمات المقاولين والشهادات** فقط، ونص داكن واضح.
- برتقالي فاتح ووسم **«تواصل من القسمين»** عند تسجيل تواصل فعلي من القسمين مع العميل نفسه.
- إصلاح تشغيل قاعدة Neon المستعادة دون الاعتماد على `crm.db.gz` غير المرفق بالكود.
- نقل 60 ملف README تاريخي وملفات استعادة قديمة إلى أرشيف منفصل خارج GitHub، دون حذفها نهائيًا.

## رفع GitHub (من الموقع)

1. **فك ضغط** ملف الحزمة النظيفة على جهازك، ولا ترفع ZIP نفسه ككود.
2. افتح مستودع GitHub **الخاص (Private)** واضغط `Add file → Upload files`.
3. ارفع `render.yaml` و`.gitignore` و`README.md` ومجلد `Alrawasi_CRM_OneClick_Deploy` بمحتوياته، مع المحافظة على نفس المسارات. لا تنشئ مجلد تغليف إضافيًا.
4. اضغط `Commit changes`. إذا كان المستودع القديم يحتوي على ملفات README القديمة بالفعل، فلن تختفي بمجرد رفع الحزمة؛ احذفها من المستودع في commit مستقل، أو استخدم Git محليًا مع مراجعة `git status`.
5. إذا كان لديك مشروع Render قائم بإعداد `rootDir` مختلف، **لا تغيّره دون فحص**. تأكد من أن `DATABASE_URL` يشير إلى قاعدة Neon الصحيحة وأنها مهيأة بالفعل.
6. يفضّل النشر على Render تجريبي أولًا مع Neon تجريبية، ثم اختبار الدخول وحفظ سجل والتحديث واستعادة البيانات بعد إعادة نشر.

## شرط مهم قبل نشر نسخة جديدة

- لا تنشر هذه الحزمة إن كانت قاعدة Neon لا تحتوي على اللقطة الكاملة السليمة؛ يبدأ التطبيق في وضع Neon **بالفشل الآمن** عند غياب البيانات.
- متغيرات Render المطلوبة: `DATABASE_URL` و`SECRET_KEY`، مع أي مفاتيح أخرى مستخدمة في `render.yaml`. ضع القيم في Render فقط، لا تضعها في GitHub.
- اترك `ALLOW_SEED_INITIALIZATION=false` لحماية القاعدة القائمة.
- هذا **وضع انتقالي** يعتمد على صورة SQLite كاملة داخل Neon، وليس تحويلًا كاملًا لجداول CRM إلى PostgreSQL.
- تحديث الكود لا يستورد ملف 326 سجل تواصل تلقائيًا ولا يبدل قاعدة Neon الحية.

## ملاحظة للمستودع الموجود مسبقًا

عند تحديث مستودع قائم بنفس البنية، يمكنك رفع الملفات المتغيرة فقط بدل استبدال كامل المشروع. وحذف الملفات القديمة من GitHub إجراء منفصل عن رفع الحزمة النظيفة.
